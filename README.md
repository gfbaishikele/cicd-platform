# AppDocker CI/CD 平台

轻量级一站式 CI/CD 持续集成与持续交付平台，集成 GitLab 代码仓库、Docker 镜像构建、私有镜像仓库管理、多节点集群部署、跨数据库同步等能力，提供 Web 可视化管理界面和实时日志推送。

---

## 技术栈

| 层级 | 技术 |
|------|------|
| 前端 | React 18 + Ant Design + Redux + React Router + Socket.IO Client |
| 后端 | Node.js + Express + Socket.IO |
| 数据库 | SQLite（sql.js WASM 编译，零外部依赖） |
| 远程执行 | SSH2（密码/密钥认证） |
| 容器管理 | Docker CLI + Docker Registry HTTP API V2 |
| 认证 | JWT 双令牌（Access + Refresh）+ bcrypt 密码哈希 |
| 加密 | AES-256-GCM（敏感凭据落盘加密） |
| AI 运维 | OpenAI 兼容 API（流式输出 + Function Calling） |

## 平台功能

### 1. 项目管理

- **业务项目**：高层级业务分组，将多个 CI/CD 项目归类到同一业务线下
- **CI/CD 项目**：关联 GitLab 仓库、Dockerfile 模板、镜像仓库，配置默认分支和构建类型
- **项目成员**：按项目分配成员和角色，实现细粒度访问控制

### 2. GitLab 集成

- 多 GitLab 实例连接管理（支持 API v4/v5）
- 在线浏览仓库和项目列表
- 获取分支列表及最新提交信息
- 构建时自动通过 OAuth2 拉取代码

### 3. Dockerfile 模板

- 内置模板变量语法 `{{variable}}`，支持自定义变量
- 按构建类型分类管理模板
- 模板预览与变量校验
- 支持系统内置模板和用户自定义模板

### 4. CI 持续构建

- **触发方式**：手动触发，支持构建后自动部署
- **构建流程**：GitLab 代码克隆 → Dockerfile 准备（模板渲染或仓库内 Dockerfile）→ Docker 构建 → 镜像推送（可选）
- **镜像标签**：自动生成时间戳标签（`yymmddhhmmss`）或自定义标签
- **实时日志**：通过 Socket.IO 推送构建日志到前端，支持日志回溯
- **构建取消**：支持取消正在进行的构建，自动清理临时镜像和容器
- **构建重试**：失败构建可一键重试

### 5. 镜像仓库管理

- 支持对接多个私有 Docker Registry（Harbor、Docker Distribution 等）
- 完整 Registry V2 API 支持：镜像列表、标签管理、镜像大小计算、标签删除
- 自动适配 Basic / Bearer Token 认证流程
- 可选 SSL 证书校验

### 6. 集群与节点管理

- **节点管理**：添加 SSH 可达的部署目标主机，支持密码和密钥认证
- **节点分组**：将节点按逻辑分组，方便批量部署
- **健康检查**：SSH 连接 + Docker 可用性检测，实时显示在线/离线状态
- **容器管理**：在线查看节点容器列表，执行启动/停止/重启/暂停操作，查看容器日志
- **节点状态**：获取远程 Docker 守护进程资源和版本信息

### 7. CD 持续部署

- **部署策略**：
  - **重建部署（Recreate）**：拉取镜像 → 删除旧容器 → 启动新容器 → 健康检查
  - **滚动部署（Rolling）**：拉取镜像 → 启动新容器（临时名称）→ 健康检查 → 替换旧容器 → 最终检查
- **多节点并行**：一次部署可同时推送到多个节点
- **应用发布**：可复用的部署配置模板，绑定项目、节点、端口、环境变量、挂载卷，支持一键「构建+部署」
- **容器配置**：端口映射、环境变量注入、卷挂载、重启策略、时区设置
- **实时日志**：部署过程日志通过 Socket.IO 实时推送
- **回滚**：支持回滚到指定历史版本的镜像
- **取消部署**：支持取消进行中的部署操作

### 8. 数据库管理

- 支持 MySQL、PostgreSQL、OpenGauss 三种数据库类型
- 连接管理：在线添加/测试数据库连接，密码加密存储
- 结构浏览：数据库 → 模式 → 表 → 字段结构，支持查看 DDL、索引、外键、约束
- **跨库同步**：MySQL ↔ PostgreSQL/OpenGauss 的表结构自动转换和数据迁移
  - 40+ 种 MySQL 类型到 PG 的映射，30+ 种 PG 类型到 MySQL 的映射
  - 自增列、外键、CHECK 约束、JSON/JSONB、注释等自动转换
  - 支持预览模式（查看转换后 DDL）和执行模式（直接迁移数据）
  - 批量同步多张表，操作审计记录
- **表分区**：基于时间维度自动创建分区表
  - 支持按月（`_YYYYMM`）和按年（`_YYYY`）分区
  - DDL 自动改写，避免索引名和注释冲突
  - 预览 + 执行两阶段操作

### 9. 用户与权限

- 用户注册与登录
- 角色区分：管理员 / 普通用户
- 管理员可管理所有用户（启用/禁用/删除）
- JWT 双令牌机制：Access Token（2h）+ Refresh Token（7d），无感续期
- 所有敏感凭据（GitLab Token、Registry 密码、SSH 密钥、数据库密码）均 AES-256-GCM 加密存储

### 10. 仪表盘

- 项目总数、构建统计、部署统计概览
- 最近构建和部署记录快速查看

### 11. AI 智能运维

- **自然语言交互**：通过对话完成构建触发、部署执行、状态查询等操作
- **流式输出**：基于 SSE 的实时打字机效果，支持思考过程可视化
- **工具调用**：AI 自动调用平台 API 查询构建记录、部署状态、节点信息、项目配置等
- **多轮对话**：支持上下文记忆，可连续追问和修正操作
- **一键执行**：AI 返回的操作建议可直接点击执行，无需手动跳转页面
- **可配置 LLM**：支持自定义 API 地址、密钥和模型名称，兼容 OpenAI 协议

## 部署指南

### 环境要求

- Docker 20.10+ 和 Docker Compose v2+
- 宿主机需开放部署端口（默认 8080）
- 构建节点需安装 Docker 并配置 `/var/run/docker.sock`

### 快速启动

**1. 获取代码**

```bash
git clone <仓库地址>
cd appdocker
```

**2. 配置环境变量**

编辑 `.env` 文件，按需修改以下配置：

```ini
# 对外访问端口
APP_PORT=8080

# JWT 密钥（生产环境务必修改为随机字符串）
# 生成方式: openssl rand -hex 32
JWT_ACCESS_SECRET=your-access-secret-here
JWT_REFRESH_SECRET=your-refresh-secret-here

# AES-256 加密密钥（用于加密 SSH 密码等敏感信息）
# 生成方式: openssl rand -hex 32
ENCRYPTION_KEY=your-encryption-key-here
```

**3. 启动服务**

```bash
docker compose up -d
```

服务启动后访问 `http://<服务器IP>:8080`，首次访问需注册管理员账号。

### 开发模式

```bash
# 安装依赖
npm install
cd client && npm install && cd ..

# 同时启动前后端（开发热重载）
npm run dev:all
```

| `./data/logs` | `/app/data/logs` | 运行日志 |
| `./data/build-logs` | `/app/data/build-logs` | 构建日志 |

## 使用指南

### 第一步：配置基础设施

1. **添加 GitLab 连接**（管理员）：进入「GitLab 连接」页面，填写 GitLab 地址、API Token，点击测试连接
2. **添加镜像仓库**：进入「镜像仓库」页面，配置私有 Registry 地址和凭据
3. **添加部署节点**：进入「集群管理」页面，添加目标主机的 SSH 连接信息，确认节点状态为「在线」

### 第二步：创建项目

1. 进入「业务项目」创建业务分组（可选）
2. 进入「项目管理」创建 CI/CD 项目：
   - 选择关联的 GitLab 仓库
   - 选择 Dockerfile 来源（模板 或 仓库内 Dockerfile）
   - 选择镜像仓库（构建后自动推送）
   - 设置默认分支

### 第三步：构建镜像

1. 进入项目详情页，点击「触发构建」
2. 选择分支，可自定义镜像标签
3. 如使用模板构建，填写模板变量
4. 构建过程中可实时查看日志输出
5. 构建成功后镜像自动推送到配置的镜像仓库（如已配置）

### 第四步：部署应用

**方式一：通过应用发布（推荐）**

1. 进入「应用发布」页面，点击「新建应用发布」
2. 选择项目，配置部署参数：
   - 目标节点或节点分组
   - 端口映射（如 `8080:80`）
   - 环境变量（如 `TZ=Asia/Shanghai`）
   - 挂载卷（如 `/host/logs:/app/logs`）
   - 容器名称、部署策略
3. 保存后点击「构建并部署」一键完成全流程

**方式二：手动部署**

1. 进入「部署管理」页面
2. 选择项目和已构建的镜像版本
3. 选择目标节点，配置容器参数
4. 提交部署，实时查看部署日志

### 第五步：运维管理

- **节点管理**：在「集群管理」页面查看节点状态、管理容器（启停/重启/查看日志）
- **回滚**：在「部署管理」页面对某次部署记录执行回滚操作
- **构建重试**：失败的构建可一键重试

## 常见问题

**Q: 构建时提示 docker.sock 权限不足？**
确保运行容器的用户有权限访问 `/var/run/docker.sock`，或将该用户加入 `docker` 组。

**Q: 部署节点连接失败？**
检查节点 SSH 配置是否正确，目标主机上 Docker 是否已安装并运行，SSH 用户是否有 Docker 执行权限（建议加入 `docker` 组）。

**Q: 镜像仓库连接失败？**
确认 Registry 地址可达，如使用 HTTP 协议的私有仓库需确认 Docker 已配置 `insecure-registries`。

**Q: 如何备份平台数据？**
备份 `./data` 目录即可，其中包含 SQLite 数据库文件和所有日志。
